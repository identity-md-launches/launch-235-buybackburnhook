# ABI exports

`LaunchToken.json` and `BuybackBurnHook.json` are standard JSON ABI arrays generated by `python3 scripts/export_abi.py` with Solidity 0.8.26. No addresses are embedded.

The token constructor takes no arguments. The hook constructor takes one `IPoolManager` (encoded as an address). `buyback` accepts a PoolKey tuple in the order `currency0, currency1, fee, tickSpacing, hooks` and is nonpayable.

`accruedEth(bytes32)`, `burnedTotal(bytes32)`, and `lastBuybackBlock(bytes32)` are read-only per-PoolId getters. The ID is the keccak256 hash of the ABI-encoded PoolKey. ETH is in wei; the approved EMBR token has 18 decimals. The hook also exposes its immutable `poolManager` and constant `FEE_BPS`, `MIN_BUYBACK`, `MAX_BUYBACK`, and `DEAD` values.

Events have an indexed `bytes32 poolId`: `FeeBurned(poolId, amount)`, `FeeAccrued(poolId, amount)`, and `Buyback(poolId, ethSpent, tokensBurned)`. `burnedTotal` includes both direct fees and buyback output. Totals count dead-address transfers and do not reduce the token's ERC-20 total supply. There is no caller payout or user credit.

Application failures include `InvalidPool`, `BelowThreshold`, `AlreadyBoughtBack`, `BuybackInProgress`, `UnexpectedCallback`, and `InvalidBuybackDelta`. BaseHook exposes `NotPoolManager` and `HookNotImplemented`. PoolManager and currency transfer errors may also bubble or be wrapped; clients should handle failed estimation/execution rather than assuming every failure has a hook-defined error selector.
